 A Interface do Usuário (UI) é responsável pela interação direta entre o operador e o sistema. Implementada como uma aplicação web responsiva, ela apresenta em tempo real os valores de temperatura e umidade coletados, disponibiliza os controles para alternância entre os modos de operação (Ligado, Desligado e Automático) e exibe alertas visuais quando os limites pré-estabelecidos são ultrapassados. A interface comunica-se com o firmware do ESP32 por meio de requisições HTTP, enviando comandos e recebendo respostas no formato JSON.

O Controle de Dados é a camada responsável por receber os dados brutos provenientes do sensor DHT11, validá-los, aplicar os procedimentos de calibração necessários e encaminhá-los às demais camadas do sistema. Essa camada implementa também a lógica de detecção de anomalias: quando um valor lido excede os limiares pré-configurados pelo usuário, o módulo aciona simultaneamente a camada de comunicação para enviar notificações por e-mail e a interface web para a exibição dos alertas e da alternância de modos.

A camada de Comunicação gerencia toda a troca de informações entre o hardware e os serviços externos. O firmware do ESP32 utiliza o protocolo HTTP/HTTPS para enviar leituras ao banco de dados remoto e para receber comandos originados na interface web.

Por fim, o Armazenamento de Dados engloba dois mecanismos complementares: o registro remoto em banco de dados relacional, acessado pela interface web para a exibição do histórico de leituras (requisito \textbf{RF06}), e o armazenamento local em arquivo \texttt{.txt} gravado na memória flash do ESP32, que garante a persistência dos dados mesmo na ausência de conectividade com a rede (requisito \textbf{RF09}).

\subsection{Descrição de Alto Nível}

\textbf{1. Camada de Hardware e Sensoriamento}

\underline{Coleta de Dados}

    O sistema utiliza o sensor DHT11 para capturar grandezas físicas de temperatura e umidade. A leitura é processada em intervalos definidos pelo modo de operação, evitando o aquecimento do sensor e garantindo a estabilidade dos dados.

\underline{Sinalização Visual}

    O controle de LEDs opera como uma interface de hardware imediata. Estados de alerta possuem prioridade sobre a sinalização de modo, acionando um ciclo de intermitência rápida (100ms) em todos os terminais de saída quando os limites de segurança são violados.

\vspace{0.5cm}

\textbf{2. Lógica de Controle (Firmware)}

\underline{Máquina de Estados}

    Modo 0 (Desligado): O sensor permanece em standby e apenas o LED de status pulsa para indicar atividade do processador.

    Modo 1 (Automático): Ativa o monitoramento contínuo e a rotina de persistência de dados.

    Modo 2 (Ligado): Mantém o monitoramento e habilita a configuração de parâmetros via rede.

\underline{Persistência de Dados e Temporalidade}

    Utilização do sistema SPIFFS para gravar arquivos de texto na memória flash interna.

    Sincronização via protocolo NTP para atribuir data e hora reais às medições, independente de hardware de relógio externo (RTC).

\underline{Servidor Web Embutido}

    Gerenciamento de rotas HTTP para servir arquivos estáticos e responder a requisições dinâmicas de API em formato JSON.

\vspace{0.5cm}

\textbf{3. Interface do Usuário e Comunicação (Front-end)}

\underline{Dinamismo da Interface}

    O arquivo index.html funciona como uma página única que se comunica com o ESP32 via requisições assíncronas (AJAX).

    Atualização em tempo real do DOM (Document Object Model) para refletir mudanças na temperatura e umidade sem necessidade de recarregar o navegador.

\underline{Painel de Controle e Feedback}

    Tradução de comandos do usuário (cliques e entradas numéricas) em parâmetros de URL para manipulação de variáveis globais no firmware.

    Exibição de notificações e estados do sensor (Online/Offline) baseada na validação de integridade dos dados recebidos do backend.

\vspace{0.5cm}

\textbf{4. Gestão de Erros e Segurança Lógica}

\underline{Tratamento de Exceções de Hardware}

    Verificação de valores nulos ou inválidos (NaN) para prevenir falhas na lógica de alerta e na gravação de logs corrompidos.

\underline{Validação de Comandos}

    Implementação de restrições de escrita; alterações de setpoints e unidades de medida são bloqueadas em modos de baixa prioridade para evitar conflitos de memória e garantir a estabilidade da operação automática.



\subsection{Fluxo de Dados}

O fluxo de operações do sistema pode ser descrito conforme os passos a seguir:

\begin{enumerate}

    \item O ESP32 inicializa, conecta-se à rede Wi-Fi e aguarda comandos ou eventos;
    
    \item O sensor DHT11 realiza medições periódicas de temperatura e umidade, enviando os dados ao ESP32;
    
    \item O ESP32 processa os dados recebidos e os encaminha ao banco de dados via requisição HTTP/HTTPS, registrando cada leitura;

    \item A interface web consulta o banco de dados e exibe os dados de temperatura e umidade em tempo real para o cliente, além de permitir a alternância entre os modos de operação;

    \item Ao receber um comando de alternância de modo, o ESP32 atualiza o estado interno e aciona o LED indicador correspondente, refletindo o modo de operação ativo. 

\end{enumerate}

\subsection{Protótipo Funcional}

Quando o sistema está em funcionamento, o hardware apresenta as seguintes características:

\textbf{Modo: Ligado} - os 3 LEDs ficam ligados ininterruptamente;

\textbf{Modo: Automático} - 2 LEDs piscam;

\textbf{Modo: Desligado} - 1 LED pisca;

\textbf{Alerta de temperatura máxima} - 3 LEDs piscando;

\subsection{Modo de Uso Básico}

\textbf{\large 1. Conexão e Alimentação}

Para iniciar, conecte a placa ESP32 ao seu computador utilizando um cabo Micro-USB de boa qualidade.
\begin{itemize}
    \item \textbf{Reconhecimento:} O computador deverá emitir um som de novo dispositivo conectado.
    \item \textbf{Alimentação:} O LED de power da placa acenderá, indicando que ela está recebendo energia.
\end{itemize}


\textbf{\large 2. Obtenção do Código (GitHub)} 

Antes de configurar a IDE, você deve baixar os arquivos do projeto diretamente do repositório oficial.

\begin{itemize}
    \item \textbf{Via Download Direto:} Acesse o repositório \url{https://github.com/din0t4/esp32_ps26.1}, clique no botão verde \textbf{"Code"} e selecione \textbf{"Download ZIP"}. Extraia os arquivos em uma pasta de sua preferência.
    \item \textbf{Via Terminal (Git):} Se você possui o Git instalado, utilize o comando:
    \begin{verbatim}
    git clone https://github.com/din0t4/esp32_ps26.1.git
    \end{verbatim}
    \item \textbf{Localização:} O arquivo principal do código estará na pasta \textbf{src}, e os arquivos do site estarão dentro da pasta \textbf{data}.
\end{itemize}


\textbf{\large 3. Preparação do Ambiente (PlatformIO)} 

Abra o arquivo extraído e prepare o software:
\begin{itemize}
    \item \textbf{Placa:} Vá em \textit{Ferramentas > Placa} e selecione \textbf{DOIT ESP32 DEVKIT V1}.
    \item \textbf{Porta:} Selecione a porta COM ativa.
    \item \textbf{Bibliotecas:} Instale \textbf{DHT sensor library, WiFi, WebServer e SPIFFS} no Gerenciador de Bibliotecas.
\end{itemize}

\textbf{\large 4. Upload do Código e Arquivos} 
\begin{itemize}
    \item \textbf{Código (.ino):} Clique em "Upload" 
    para gravar a lógica.
    \item \textbf{Interface Web:} Use a ferramenta \textbf{ESP32 Sketch Data Upload} para enviar a pasta \textbf{data}.
\end{itemize}


\textbf{\large 5. Inicialização e Conexão Wi-Fi} 

Abra o Monitor Serial em \textbf{115200 baud}.
\begin{itemize}
    \item A placa exibirá o \textbf{IP: 192.168.x.x}. Anote este número para acessar o dashboard pelo navegador.
\end{itemize}


\textbf{\large 6. Operação do Sistema} 
\begin{itemize}
    \item \textbf{Troca de Modos:} Escolha entre Desligado, Automático ou Ligado.
    \item \textbf{Configuração:} No modo \textbf{Ligado}, ajuste a temperatura máxima e a unidade (°C/°F).
    \item \textbf{Histórico:} Clique em \textbf{Baixar Histórico de Logs} para obter o arquivo \textit{log.txt}.
\end{itemize}
